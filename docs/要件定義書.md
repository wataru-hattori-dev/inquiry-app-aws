## 1. 機能概要 / 目的

### 1.1 目的

お問い合わせの作成・一覧確認・削除を提供する、サーバーレス Web アプリケーションを構築する。

### 1.2 機能概要

| ID | 機能 | 概要 |
|----|------|------|
| F-01 | 作成 | お問い合わせを新規登録できる |
| F-02 | 一覧確認 | 登録済みのお問い合わせ一覧を確認できる |
| F-03 | 削除 | 指定したお問い合わせを削除できる |

### 1.3 アーキテクチャ（要件としての技術前提）

| レイヤ | 技術 |
|--------|------|
| フロントエンド | React + TypeScript（Vite） |
| API | Amazon API Gateway（HTTP API） |
| バックエンド | AWS Lambda（Python 3.11） |
| データストア | Amazon DynamoDB |
| IaC / デプロイ | AWS SAM（`template.yaml`） |

## 2. 前提・対象外

### 2.1 前提

- インフラは AWS SAM の `template.yaml` で定義・デプロイする。
- DynamoDB テーブル名は `InquiriesTable`。パーティションキーは `id`（String）。ソートキーはなし。
- API は HTTP API（`InquiryApi`）とし、パスは次のとおりとする。
  - `POST /inquiries` … 作成
  - `GET /inquiries` … 一覧
  - `DELETE /inquiries/{id}` … 削除
- Lambda ランタイムは Python 3.11。Timeout 10 秒、Memory 128 MB、アーキテクチャ x86_64。
- 各 Lambda は環境変数 `TABLE_NAME` でテーブル名を参照する。
- IAM は最小権限とする。
  - 作成: `DynamoDBWritePolicy`
  - 一覧: `DynamoDBReadPolicy`
  - 削除: `dynamodb:DeleteItem` のみ（`DynamoDBDeletePolicy` 相当のインラインポリシー）
- CORS（API Gateway）は次を許可する。
  - Methods: `GET`, `POST`, `DELETE`, `OPTIONS`
  - Headers: `Content-Type`, `Authorization`
  - Origins: `*`
- フロントエンドは API エンドポイント URL 等を `.env` 経由で参照する。
- TypeScript の型定義は厳格に行い、`any` の多用を避ける。
- バックエンド・フロントエンドのソースは、現状リポジトリに未作成である（ディレクトリ想定のみ確定）。

### 2.2 対象外（根拠資料で要求されていないもの）

次は初期要件の対象外とする（根拠資料に明示がないため）。

- 問い合わせの更新（UPDATE）
- 問い合わせ詳細の単体取得 API（`GET /inquiries/{id}`）
- 認証・認可の実装（Cognito 等）。ただし CORS で `Authorization` ヘッダーは許可されている
- メール通知、検索、フィルタ、ページネーション（未記載のため非対象）
- フロントエンドのホスティング方式（S3 / CloudFront 等）の確定

## 3. ユースケース（正常系）

### UC-01 お問い合わせを作成する（F-01）

1. 利用者がフロントの投稿フォームに問い合わせ内容を入力し、送信する。
2. フロントが `POST /inquiries` に JSON ボディを送る。
3. サーバーが問い合わせを DynamoDB に保存する。このとき `id` と `created_at`（ISO 8601）を必ず付与する。
4. サーバーが `201` と、作成された問い合わせオブジェクト（少なくとも `id`, `created_at` を含む）を返す。
5. フロントが結果を利用者に提示する。

### UC-02 お問い合わせ一覧を確認する（F-02）

1. 利用者が一覧画面を開く（または一覧を再取得する）。
2. フロントが `GET /inquiries` を呼び出す。
3. サーバーが登録済み問い合わせの配列を `200` で返す。
4. フロントが一覧を表示する。

### UC-03 お問い合わせを削除する（F-03）

1. 利用者が一覧上で対象を選び、削除を実行する。
2. フロントが `DELETE /inquiries/{id}` を呼び出す。
3. 対象が存在する場合、サーバーがレコードを削除し、成功レスポンスを返す（成功ステータスは「8. 不明点リスト」参照）。
4. フロントが一覧を更新する。

## 4. データ要件

### 4.1 必須フィールド（確定）

問い合わせレコードには、少なくとも次を含める。

| 属性 | 型 | 説明 |
|------|----|------|
| `id` | String | 一意な識別子（UUID 等） |
| `created_at` | String | 作成日時（ISO 8601。例: `2026-10-01T12:00:00+09:00`） |

### 4.2 作成リクエストで想定されるフィールド（例として確定）

`AGENTS.md` の API 例より、作成時 Body の例は次とする。

```json
{
  "name": "...",
  "email": "...",
  "message": "..."
}
```

※ `name` / `email` / `message` を必須項目とするか、型・文字数・形式の規則は未確定（「8. 不明点リスト」）。

## 5. API 要件

ベース URL: SAM Output `ApiEndpoint`  
（`https://{InquiryApi}.execute-api.{AWS::Region}.amazonaws.com`）

### 5.1 共通

- エラー時は、HTTP ステータスコードに加え、必ず次の JSON 形式とする。

```json
{
  "error": "ErrorType",
  "message": "Human-readable error message"
}
```

- エラー種別の例（確定）:

| HTTP | error | 用途例 |
|------|-------|--------|
| 400 | `ValidationError` | バリデーションエラー（例: `email is required`） |
| 404 | `NotFound` | 未検出（例: `Inquiry not found`） |
| 500 | `InternalServerError` | サーバーエラー（例: `Unexpected error occurred`） |

- バックエンド応答には適切な CORS ヘッダーを含める。
- 500 時も上記 JSON 形式で返す。

### 5.2 POST /inquiries（作成）

| 項目 | 要件 |
|------|------|
| 成功 | `201` と作成オブジェクト（`id`, `created_at` を含む） |
| 失敗例 | `400 ValidationError` / `500 InternalServerError` |

### 5.3 GET /inquiries（一覧）

| 項目 | 要件 |
|------|------|
| 成功 | `200` と問い合わせ配列 |
| 失敗例 | `500 InternalServerError` |

※ レスポンスが素の配列か、ラップオブジェクトか、並び順は未確定。

### 5.4 DELETE /inquiries/{id}（削除）

| 項目 | 要件 |
|------|------|
| 成功 | `204`、または `200` と削除結果（いずれか。未確定） |
| 対象なし | `404`（`NotFound`） |
| 失敗例 | `500 InternalServerError` |

## 9. テスト観点（概要）

| 観点 | 内容 |
|------|------|
| T-01 作成正常系 | `POST /inquiries` が `201`、返却に `id` / `created_at` を含む |
| T-02 一覧正常系 | `GET /inquiries` が `200` と配列を返す |
| T-03 削除正常系 | 既存 ID の `DELETE` が成功ステータスで完了し、以降一覧に現れない |
| T-04 削除 404 | 存在しない ID で `404 NotFound` |
| T-05 バリデーション | 不正入力で `400 ValidationError`（具体規則確定後に詳細化） |
| T-06 エラー形式 | 4xx/5xx が共通 JSON（`error`, `message`）である |
| T-07 CORS | ブラウザからの GET/POST/DELETE が CORS 上許可される |
| T-08 IAM | 各関数が必要最小限の DynamoDB 操作のみ可能である |
| T-09 FE 結合 | 作成・一覧・削除の一連操作が UI から可能である |
